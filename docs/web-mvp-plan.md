# Sage Web MVP 细化计划

## 0. 目标

在不引入 Tauri/macOS 壳的前提下，把 Sage Mac 的核心能力迁移到浏览器，优先验证：

- 谁会使用 Sage
- 他们会如何使用 Sage
- 哪些能力值得继续投入

---

## 1. 里程碑拆分

### Phase 1：Web 启动壳收口
**目标**：浏览器打开即可使用，启动链路不再依赖桌面壳。

#### 必做项
- 移除 `main.tsx` 中的 sidecar 就绪轮询
- 更新器 provider 变成 Web-safe no-op
- 主题 provider 不再同步原生窗口主题
- `package.json` 只保留 web / api 命令

#### 验收标准
- `pnpm dev` 可以在浏览器直接启动
- 首页能渲染，不依赖任何 `@tauri-apps/*` 运行时能力

---

### Phase 2：登录与会话恢复
**目标**：用户能登录、刷新后能恢复会话、Auth 状态稳定。

#### 必做项
- Supabase OAuth web 登录
- 登录后 session 恢复
- AuthGuard / SetupGuard 保持可用
- 当前账号绑定对应本地缓存 / IndexedDB

#### 验收标准
- 从未登录到登录完成闭环正常
- 刷新后仍能恢复登录状态

---

### Phase 3：核心对话链路
**目标**：用户可以在 web 里正常和 Agent 对话。

#### 必做项
- 首页输入框
- SSE 流式输出
- plan/execute 路由
- 任务详情页
- 错误提示与重试

#### 验收标准
- 发一句话，能得到完整回答
- 复杂任务可进入任务页查看执行过程

---

### Phase 4：记忆与历史
**目标**：让用户感到 Sage 记得上下文。

#### 必做项
- 会话列表
- 历史会话恢复
- persona / memory 同步
- 基础 profile 展示

#### 验收标准
- 用户能找到历史会话并继续聊
- 同一用户再次登录时上下文能延续

---

### Phase 5：金融核心能力
**目标**：保留 Sage 最核心的金融差异化。

#### 必做项
- 股票快照
- K 线 / 分时
- 新闻 / 研报摘要
- 基础选股 / 数据表

#### 验收标准
- 用户能用 Sage 看行情和图表
- 核心金融卡片能在浏览器正常呈现

---

### Phase 6：设置与可观测性
**目标**：让用户能配置模型和看见反馈。

#### 必做项
- Model/Provider 配置
- 基础数据导出
- 关于页版本信息
- 基础埋点

#### 验收标准
- 用户能自助配置模型
- 能导出基础数据
- 能知道当前版本和环境

---

## 2. Web 版暂缓项

- Tauri updater / notarization / signing
- 本地安装包与桌面分发
- deep-link 登录回调
- sidecar / native shell
- 本地文件系统路径迁移
- 高级离线能力

---

## 3. 代码重整方向

### 目录层次
- `app/`��路由、布局、providers、启动
- `pages/`：页面入口
- `widgets/`：组合型 UI
- `features/`：业务能力
- `entities/`：领域模型
- `shared/`：通用基础设施

### 重整原则
1. 先把桌面依赖从入口处收口
2. 再把业务模块按职责拆分
3. 最后优化目录结构，不反向影响功能推进

---

## 4. 执行顺序

1. 启动壳收口
2. 登录与会话恢复
3. 核心对话与任务链路
4. 历史与记忆
5. 金融能力
6. 设置与埋点
