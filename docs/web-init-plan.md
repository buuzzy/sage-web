# Sage Web 初始化方案

## 一、目标

未来几个月，Sage 以 **Web 端为主** 做市场验证，重点回答三个问题：

1. 谁会真正使用 Sage
2. 他们会把 Sage 用在什么场景
3. 哪些能力值得继续投入

macOS 项目保留在本地冻结，不作为当前主开发线。

---

## 二、仓库策略

### 1. 当前 macOS 项目
- 本地保留
- 不继续大改
- 只做必要修复或回溯参考

### 2. 新 web 项目
- 新建独立本地文件夹
- 新建独立 GitHub 仓库
- 只承载 web 产品逻辑、前端体验和云端协作

### 3. 旧历史仓库
- 保持归档属性
- 只在需要回顾设计演进时参考

---

## 三、首期必须保留的能力

- 登录 / 注册
- 核心对话
- Agent 执行与规划
- 连续记忆
- 金融信息与图表
- 云端同步
- 基础埋点

---

## 四、首期暂缓的能力

- macOS 安装包与签名
- Tauri updater
- 本地文件系统与桌面路径
- sidecar 模式
- 桌面专属导入 / 导出
- 任何依赖原生窗口或 deep-link 的逻辑

---

## 五、迁移原则

1. 先把能复用的业务代码、后端代码、数据模型迁过来
2. 再逐步清理桌面专属依赖
3. 先保证能验证 PMF，再优化工程结构
4. 不为了“统一架构”牺牲迭代速度

---

## 六、推荐节奏

### Phase 1：建仓与迁移
- 初始化 web 仓库
- 迁移可复用文档、前端、后端、数据模型
- 清理明显的桌面专属入口

### Phase 2：跑通 web MVP
- 登录
- 发消息
- 记忆延续
- 基础金融任务

### Phase 3：真实用户验证
- 收集使用反馈
- 观察留存和高频场景
- 决定是否重启 macOS 产品设计
