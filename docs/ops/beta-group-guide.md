## 群规（6 条）

1. **请勿在群外分享邀请码**——一码一批，泄露将立即停用，影响大家测试
2. **不讨论买卖建议**——Sage 输出仅供研究，不构成投资建议
3. **遇到问题先复现**：报错截图 + 你的操作步骤（打开哪个 tab、点过什么、输入什么），不要只说"不好用"
4. **不要刷屏测试无意义请求**，给真实场景一些带宽
5. **尊重他人隐私**——不截图他人的对话内容、不替他人发言
6. **每周五填 1 分钟周报**——4 道题，是你看板数据的真实写照

## 入群流程

1. 加你的微信号（运营者）
2. 填写入群问卷（见 `onboarding-survey.md`），目的是了解背景 + 后续追踪
3. 拉入微信群
4. 在 `/admin` 看板上**生成一个 batch 码**（见下方"兑换码发放操作"）
5. 私聊发送兑换码（不直接发群里，避免泄露）
6. 对方在 sage-web 注册页输入邮箱 → 邮箱验证码 → 兑换码 → 进入产品
7. 群里发"已进入"，你到 `/admin` 看到激活数 +1

## 兑换码发放操作（看板流程）

**为什么一码一批**：每个码 1 个 `note` 字段 + `code_redemptions` 流水 = 天然渠道归因。出问题时能立刻知道是哪个码、什么时间、被谁用。

操作步骤：
1. 打开 `/admin`（首次需输入 `ADMIN_TOKEN`）
2. 找到「兑换码管理」面板
3. 「批次上限」按本批人数设（建议 `max_uses = 1`，每人一个码，便于追踪）
4. 「备注」写清渠道（如 `WAVE1-熟人张三`、`WAVE2-金融群-李四`）
5. 点「生成兑换码」，表格里出现新行
6. 点行末复制按钮 → 私聊发给用户
7. 退群 / 外泄 / 异常 → 行首 Switch 关掉，立即生效

> ⚠️ 码一旦被某用户兑换，`used_count` 就会 +1，无法"回收"。批量码（`max_uses > 1`）被外传会有失控风险——除非你已经权衡过。
> 推荐每人一码，宁可多花 1 分钟复制。

## 每周节奏

| 时机 | 动作 |
|---|---|
| **周一** | 看 `/admin`：上周激活率、D1/D7、近 7 天提问数、是否有 code_redemptions 突变 |
| **周三** | 看 `error_logs`（Supabase 控制台）有没有错误堆积，发现明显 bug 立即修 |
| **周五 16:00** | 在群里发本周 `changelog`（什么修了、什么加了） |
| **周五 18:00** | 发周报问卷（4 题，见 `weekly-survey.md`） |
| **周末** | 挑 1~2 个回答有信号的用户私信约下周的访谈 |

## 第一阶段结束（~4 周后）的复盘清单

- [ ] 拉出 4 周的总览 +漏斗 + 留存 cohort 趋势
- [ ] 把 5~8 个访谈的 Sean Ellis 选项统计出来（A 占比 = 非常失望 %）
- [ ] 周报 NPS 平均分（看变化趋势）
- [ ] 列出最常被提到的 3 个痛点 + 缺失功能
- [ ] 决定：继续内测 / 扩大内测 / 公测 / 转向
